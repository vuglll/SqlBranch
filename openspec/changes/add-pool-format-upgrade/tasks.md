# Tasks

Every Docker test in every group is an integration test tagged so it runs only when `SQLBRANCH_IT=1`. "Regenerate the agent skill" means `dotnet run --project src/SqlBranch.Cli -- skill export --dir skills/sqlbranch --force` and committing `skills/sqlbranch/`; the unit suite's comparison must pass. Until task 4.2 exists, tests that need a format-2 pool get one from a test helper that writes the format-2 layout (D2, D3, D5) directly; after 4.2 the integration tests also build one with `pool upgrade --yes`.

## 1. Verify platform assumptions

This group runs first after approval, on the maintainer's Linux machine, where Docker is available. Record environment, date, observed results and source links in `docs/research/2026-11-24-pool-format-upgrade-facts.md`. A failed check means revising design.md before relying on the fact.

- [ ] 1.1 On a directory pool and a loop-xfs pool, one of them in copy mode, run the D2 rewrite sequence by hand and kill the writer, then restart the engine, at each step (temp write, chown, chmod, sync, rename, directory sync). Also kill a client holding a session application lock in `master` and check the lock is released. Verify: after each kill the credentials file parses as the complete old or the complete new content with mode 600 and owner 10001, a rerun of the sequence succeeds, and the lock is free within the observed time. The kill matrix is in the research note.
- [ ] 1.2 Install the released `sqlbranch` 0.2.2 tool from NuGet. On a format-1 pool, add the D5 fields to one `branch.json` by hand and run 0.2.2 `image list`, `branch list` and `image export`. Verify: the observed exit codes and output are recorded; if 0.2.2 fails on the new fields, revise D5 before task 3.6.

## 4. The upgrade command

- [ ] 4.1 Add `sqlbranch pool upgrade` parsing: `--yes` required, no value, not repeated, no operand, no other option; then `not_initialized` and `engine_stopped` checks. Verify: the "Upgrade input table" and "Missing confirmation" scenarios with zero Docker calls, and both exit-3 scenarios. Add the command metadata (destroys: compatibility with 0.2.x tools) and the guardrail text from the agent-skill delta to the skill generator; regenerate the agent skill. Verify the two agent-skill scenarios. Add the synopsis to `docs/engine.md`.
- [ ] 4.2 Implement upgrade steps 1, 3 and 5 of D6 for an idle pool: fence, first IDs from the recorded start time, catalogs, high-water marks, text and JSON output, the stderr warning in both formats, and "already format 2". Verify: fake-clock tests for "First version IDs", "Upgrade JSON", "Upgrade text", "Upgrade twice" and the sentinel-password scenario; integration test "Upgrade a pool with images and branches" in both clone modes.
- [ ] 4.3 Implement branch binding (step 4 of D6): pinned, unknown and removed bases, reported in `branches`. Verify: "Branch older than its image" and "Branch of a removed image" with a fake clock, and that `branch list` and plain reset then show the bases from task 3.6.
- [ ] 4.4 Implement the wait (step 2 of D6): poll every image and branch lock without waiting until `publishWait`, stderr progress, `catalog_busy` naming the busy item. Verify: fake-clock tests for "Branch create still running" and both configuration-delta wait scenarios.
- [ ] 4.5 Make an unfinished upgrade block writes with `pool_upgrade_required` while list, export, conn and status keep working; make a rerun resume from the recorded state, remove a leftover temp file, and stop with `pool_full` when space runs out. Verify: kill at each step of D6 and of the credentials rewrite (fake runtime) and rerun with identical IDs; "Create during an unfinished upgrade", "Killed in the middle", "Pool full while writing catalogs", "Killed while rewriting the credentials" and both status scenarios. Document in `docs/engine.md` that a timed-out or interrupted upgrade blocks writes until `sqlbranch pool upgrade --yes` is rerun, and how `status` shows it.
- [ ] 4.6 Make every command that changes images or branches re-read the format after taking its locks, and report environment errors in the D8 order. Verify: "Upgrade starts while a create waits for its lock" and both "Order of environment errors" scenarios with a fake runtime; "Other commands do not upgrade".
- [ ] 4.7 Adopt items a 0.2.2 command wrote after the upgrade (D7). Verify: "Image written by 0.2.2 after the upgrade", "Branch written by 0.2.2 after the upgrade" and "Name used by an image an older client wrote", with legacy files written directly. Document the "stop 0.2.x tools first" advice in `docs/engine.md`.
